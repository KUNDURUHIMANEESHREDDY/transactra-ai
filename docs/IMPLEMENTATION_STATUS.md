## Current operational safeguards

- No paid-provider fallback.
- NIM inference is blocked unless the no-cost entitlement and monthly caps are configured.
- Tavily uses Basic Search only, with an internal cap of 800 credits/month against its documented 1,000-credit free allowance. The worker requires an operator attestation that PAYG is disabled.
- New project repositories are private by default and deterministically named per task.
- The GitHub adapter rejects new branch creation, PR creation and PR merging against Transactra. Repository metadata nevertheless currently shows an unmerged five-commit sandbox branch in addition to `main`; the single-branch invariant is therefore not satisfied until the owner resolves that branch under repository policy.
- Sensitive Transactra main-branch writes, PR merges, deployments, destructive operations and permission changes are approval-gated.
- Project generation is not marked tested: the current innovation executor creates a documented private scaffold and CI workflow, but does not execute generated code in an isolated sandbox.
- Every agent shares one `ToolGateway`, so audit records, capability grants, approvals and secret screening are single-sourced. An agent whose capability grant is not fully registered is dropped from the executable workforce catalogue rather than executed with reduced permissions.
- Self-evolution changes are confined to application, package, documentation, test and migration paths; dependency manifests, lockfiles, CI permissions, credential files, key material and parent-directory traversal are rejected, each change set is schema- and secret-screened, and the workspace must pass the isolated sandbox verification before the change can be applied. Apply and rollback both require a fresh owner approval.
- Deployment dispatch and rollback are always approval-gated, are pinned to a full 40-character commit SHA plus an explicit environment input, and rollback re-dispatches the last previously successful commit for the same repository and environment.
- Owner notifications are claimed with row locks per channel surface, so the same alert is delivered exactly once, while the local surface is pull-based and is only marked delivered after an authenticated owner acknowledgement.
- The web dashboard is served from the control plane with a per-request CSP nonce, has no build step and no third-party runtime, never holds a credential beyond session storage, and can only mutate state through the documented approval-gated endpoints.
